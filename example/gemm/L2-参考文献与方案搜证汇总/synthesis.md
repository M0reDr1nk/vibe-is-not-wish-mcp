## ⚠️ 遗留歧义（按用户新增要求：模糊需求需反向提问）

在拆解与搜证中发现原始需求"做一个本机 CPU GEMM 加速实现"存在 3 个影响架构的关键歧义，需人工确认后才能进入 L3：

| 编号 | 歧义点 | 影响 | 推荐默认 |
|------|--------|------|---------|
| A1 | 是否允许直接调用系统 BLAS（Accelerate）作为交付实现？ | 决定 L3/L4 是否完全手写；若允许则工作量骤降但失去"实现"意义 | **手写**，Accelerate 仅作对照 |
| A2 | 精度范围是否仅 float32？ | 若需 float64 则微内核宽度减半、参数重算 | **仅 float32** |
| A3 | 目标矩阵规模偏向？ | 小矩阵（<256）需考虑切换轻量内核；大矩阵才吃分块收益 | **偏中大规模 512–4096**，小矩阵走简化路径 |

> 这三个问题若由 agent 自行假设，错误会在 L4/L5 才暴露，重做成本高。故在 L2 结束处显式提出，等待确认。

## 歧义澄清结果（人工确认，2026-11-14）

| 编号 | 追问内容 | 用户答复 | 对设计的影响 |
|------|---------|---------|-------------|
| A1 | 是否允许直接调用 Accelerate 作为交付 | **手写实现**，Accelerate 仅作 bench 上界对照 | L3/L4 必须完整实现分块+打包+微内核；bench 中保留 `--ref-blas` 对照项 |
| A2 | 精度范围 | **仅 float32** | 微内核 4×8、NEON 128-bit（4×f32）向量化；不做 double 路径 |
| A3 | 目标规模 | **中大规模 512–4096** | 分块参数按该区间调优；小于 256 时走简化路径（跳过打包，直调微内核）并标注"非调优区间" |

> 过程记录：这 3 个问题若由 agent 自行假设，A1 猜错会导致整个 L3/L4 路线作废（手写 vs 调用 BLAS 工作量差一个数量级）。该次追问已作为"模糊需求反向提问"能力的首个实战案例。

## descent-3 补充：性能基线与硬件上限实测（2026-11-14）

### 实测数据（Apple M3，4P+4E，-O3 -march=native -ffast-math）

| 项目 | 单线程 GFLOPS | 说明 |
|------|-------------:|------|
| 真·朴素 ijk | 3.56 | 内层步长 N，无法向量化（256³ 缩放测得） |
| ikj（原 bench 基线） | 23.64 | 缓存友好 + 8 宽 FMA 向量化 |
| 本项目 blocked 1T | 25.14 | 4×8 微内核 + 打包 |
| 本项目 blocked 8T | 109.19 | 4.34× 扩展（4P+4E 混合） |
| Accelerate cblas | 1597 | AMX 协处理器 |
| 显式 SIMD FMA 峰值 | **38.5** | 8 个独立 v4 累加器，单核算力上限 |

### 关键论证

1. **ikj 基线是访存受限还是算力受限？** ikj 每 FLOP 约需 2 字节读取，23.64 GFLOPS ≈ 47 GB/s 的 L2/L3 带宽，
   （每 FLOP 需 2 字节读：23.64 GFLOPS ≈ 47 GB/s）而单核算力上限 38.5 GFLOPS → ikj 已达算力峰值的 61%，说明它同时吃到了缓存与向量化红利，
   不是"朴素基线"，而是"已优化基线"。
2. **「相对 ikj 8×」的实际含义**：189 GFLOPS = 整机估算峰值（4×38.5 + 4×~20 ≈ 234）的 **81%**。
   纯 C + 自动向量化（R6 约束）在 1024³ 上达到整机 81% 效率不现实（手写 intrinsics + 汇编微内核才可能）。
3. **「相对朴素 ijk 8×」**：门槛随基线尺寸而定——256³ 基线 3.56 GFLOPS → 需 28.5 GFLOPS；
   1024³ 基线 1.74–1.93 GFLOPS → 需约 14–15 GFLOPS。descent-3 最终口径：**验收尺寸固定 1024³**，
   基线用同尺寸单线程 naive-ijk（实测 1.74–1.93，随机器负载浮动），故门槛 ≈ 14–15 GFLOPS。
   实测 blocked-1T 在 1024³ 为 38–40 GFLOPS → 19.9–24.8× ✅
4. **线程扩展**：4 线程 90.24（P 核满载），8 线程 109.19（+E 核收益递减）→ 4.34×；
   理论上限约 (4×38.5 + 4×20)/38.5 = 6.1×，需优化负载均衡与内存带宽占用。

### 结论

- 验收门槛采纳用户裁定：**8× 相对真·朴素 ijk**（双基线），**尺寸固定 1024³、基线为同尺寸单线程实测**
- 性能数字必须标注（尺寸, 线程数）——descent-3 评审指出跨层数字口径不一致，已统一
- ikj 与 Accelerate 作为上限参照，不再作为门槛
- ST 优化方向：微内核 k 方向展开（2~4）+ 减少 A 面板指针运算 + 可选 8×8 分块（寄存器压力需实测）
- MT 优化方向：E 核负载均衡（按算力加权分块）、减少 B 面板串行打包
