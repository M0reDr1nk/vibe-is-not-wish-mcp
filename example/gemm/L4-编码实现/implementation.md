### 1. 双基线 bench（L1 裁定 both-baselines）

- `gemm_f32_naive_ijk`：真·朴素 ijk 参考（验收基线）
- bench 输出四实现 + 门槛行：`gate blocked/naive-ijk = XX.XXx (门槛 8x: PASS/FAIL)`
- ikj 与 Accelerate 保留为上限参照

### 2. NEON 微内核优化

- 指针提升 + k 方向 2 路展开
- 实验结果：4×8 / 4×12 / 6×8 / 8×8 四种 tile 形状实测差异 < 2%（25.14 → 25.66 GFLOPS）
- 结论：clang 对 4×8 已充分向量化，形状调优收益有限

### 3. AMX 后端（实验性，`make USE_AMX=1`）

**可行性验证（关键发现）**

| 发现 | 结论 |
|------|------|
| 用户态 AMX 在 M3 + 当前 macOS **可用**（无 SIGILL） | corsix/amx 官方测试套件 10+ 指令全部 OK |
| 单寄存器 `ldx/ldy`（bit62=0）**与 pair load 均可用**（首版结论有误：早期测试把数据装 Y[1] 却用 yoff=0 读 Y[0]） | 本实现选 pair load 减少指令数；代价是奇数 k 尾多读一行 → B 加哨兵行 |
| pair load 要求相邻两个 k/相位步**内存连续** | B 必须块状打包 `[n_tile][k][16]` |
| 首版 `-O3` 崩溃经定位为**整数移位 UB**（`row << 56` 对 int），已修；现 `-O3` 正常 | 已移除 -O2 特例 |

**实现**

- tile = 64(M) × 16(N)，fma32 四相位累积（每相位 16 行）
- A 按 m 块打包 `[k][64]`（每 m 块一次）；B 全局一次块状打包 `[n_tile][k][16]`
- 边角块（M 非 64 倍数 / N 非 16 倍数）用朴素 ikj 补算；奇数 K 尾由哨兵行保证不越界
- 未编译 AMX 时符号存在但返回 `GEMM_EINVAL`，调用方回退

**实测（1024³，单线程 AMX）**

| 实现 | GFLOPS | 相对朴素 ijk |
|------|-------:|------------:|
| naive-ijk | 1.74 | 1× |
| naive-ikj | 17.69 | 10× |
| NEON blocked（8 线程） | 119.25 | 69× |
| **AMX 后端（单线程）** | **866.62** | **499×** |
| Accelerate cblas | 1326 | 762× |

AMX 单线程即达 NEON 8 线程的 7.3 倍、Accelerate 的 65%——验证了「自研 AMX 内核」的技术路径成立。

**诚实披露**：AMX 未文档化、平台锁定（M1–M4）、与 Accelerate 同进程混用需隔离（bench 已分段执行）；生产使用需自行评估风险。

**评审更正**（reviewer16）：pair-load 必需与 -O3 必崩两条结论均已被证伪并更正；R4 扩展性实测 3.22× < 4× 门槛，如实记录 FAIL。

## descent-4：R4 扩展性优化尝试（未达标，如实记录）

### 尝试与结果

| 方案 | 8T/1T | 结论 |
|------|------:|------|
| v003 基线（MC=128, NC=2048, 静态等分） | 3.22×（同机受控复测 2.53~2.66×） | 未达 4× |
| MC=64 细粒度 + 按 perflevel 加权分块 | 2.20~2.66× | **更差**：B 面板重读翻倍，内存带宽成为瓶颈 |
| MC=64 + 保底1块+最大余数法 | 2.45× | 修了"第 7 个线程分 0 块"的舍入 bug，仍差 |
| **事后发现**：原分配在 nb=16/nt=8 时退化为等分 | — | 加权**从未真正生效**；现已重写为理想块数分配，但 MC=128 时 nb==nt 仍等价等分 |
| MC=128 + NC=512（缩小 B 面板） | 2.79× | 比值略升但绝对性能下降 |
| MC=128 + 加权（8 块 8 线程 → 退化为等分） | 2.53~3.22× | 与基线等价 |

### 结论

1. **加权分块未能在不牺牲缓存的前提下生效**（原表述"假设被证伪"不准确，评审 INC-002 更正）：
   要把 MC 降到 64 才有 nb>nt 的加权空间，而 MC=64 放大 B 面板重读、净损失更大；
   MC=128 时 nb==nt，加权必然退化为等分
2. **测量方差存在但 4.34× 不可复现**（评审 GAP-003 更正）：该值来自 descent-2 早期二进制
   （109.19/25.14），不是本轮二进制；本轮同二进制多次实测 2.53×~3.30×；
   R4 判定必须标注测量条件（本报告采用一次受控测量：**2.66×**）
3. **R4 仍 FAIL**，未改门槛。剩余差距归因于硬件（4P+4E 混合核）+ 内存带宽，
   继续优化的正确方向是**减少 B 面板流量**（如 NC=256 + 多级阻塞）或**用 AMX 后端扛主算力**（AMX 单线程已 866+ GFLOPS）

### 保留的代码改进

`parallel_for_m` 现为「保底 1 块 + 最大余数法 + perflevel 权重」：
- 8 块 8 线程时退化为等分（与 v003 等价），无回归
- 块数 > 线程数时按算力加权，为后续更大规模留下空间
- 修复了 round(累计比例) 导致末线程分 0 块的 bug
