# descent-7 选型评估矩阵

## 决策 A：注册表存储介质

| 维度（权重） | JSON 单文件 | SQLite | 目录扫描（无注册表） |
|-------------|------------|--------|---------------------|
| 人类可读 / git diff（3） | ✅ 3 | ❌ 0 | ✅ 3 |
| 实现复杂度（3） | ✅ 3 | ⚠️ 1（schema/迁移/连接管理） | ✅ 3 |
| 原子写 / 并发安全（2） | ⚠️ 1（需 tmp+rename + 文件锁） | ✅ 2 | ✅ 2（无共享状态） |
| 大规模性能（1） | ⚠️ 1（>500 项目时读全量） | ✅ 1 | ⚠️ 1 |
| 可编辑/可修复（2） | ✅ 2 | ⚠️ 1 | ✅ 2 |
| 与 VINW「Markdown-first」理念一致（3） | ✅ 3 | ❌ 0 | ✅ 3 |
| **合计（14）** | **13** | **5** | **14** |

**定论**：JSON 单文件（`~/.vinw/registry.json`）+ 原子写（tmp + `os.replace`）+ 可选文件锁。
目录扫描方案得分同为 14，但无法保存「用户显式登记」与「最近访问时间」，故取 JSON；扫描作为**补充发现手段**（加入注册表时自动探测）。
SQLite 被否决：优势场景（数千行、高频事务、多进程强一致）在本需求中不存在，却牺牲可读性与实现复杂度。

## 决策 B：失效工程策略

| 方案 | 数据安全 | 用户可预期 | 实现复杂度 | 结论 |
|------|---------|-----------|-----------|------|
| 加载时自动删除缺失条目 | ❌ 移动/暂离挂载盘即丢登记 | ❌ 静默 | 低 | **否决**（违反「不得静默删除」约束） |
| 仅标记 stale，提供显式 prune | ✅ 不丢 | ✅ | 中 | **采纳** |
| 每次访问探测，不登记状态 | ✅ | ⚠️ 每次 I/O | 低 | 作为底层探测手段采纳 |

**定论**：三层结合
1. **读取时探测**：`list_projects` 对每条探测 `<root>/.vinw/manifest.md`，输出 `status: ok | missing`
2. **持久状态**：探测结果写回 `last_seen_ok` / `missing_since`，不删除条目
3. **显式清理**：`vinw project prune` / `se_prune_projects` 删除 missing 条目，`--dry-run` 默认

## 决策 C：工程身份标识

| 方案 | 重名 | 路径移动 | 结论 |
|------|------|---------|------|
| 名称寻址 | ❌ 冲突 | ✅ 不受影响 | 作为**别名**辅助 |
| 绝对路径寻址 | ✅ | ❌ 断链 | 作为**主键** |
| 稳定 UUID | ✅ | ⚠️ 需同步 | 过度设计 |

**定论**：主键 = 规范化绝对路径；名称作为唯一别名（重复注册同名但不同路径时追加 `-2` 后缀并给出警告）。
